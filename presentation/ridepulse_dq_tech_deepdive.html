Executive Architectural Overview

DataPulse — Autonomous AI Data Quality & Anomaly Intelligence

Giải pháp AI Agent tự động hóa khảo sát dữ liệu, đề xuất quy tắc chất lượng (DQ Rules), biên dịch dbt/SQL có kiểm soát và chẩn đoán dị thường kết hợp Thống kê & LLM Reasoning.

🚨 Vấn đề Thực tiễn PAIN POINT
  • Data Engineers mất hàng tuần viết và duy trì hàng trăm test dbt thủ công.
  • Dữ liệu vận hành (taxi, e-commerce, telco) xuất hiện giá trị âm, rỗng, sai định dạng.
  • Thiếu cơ chế tự động phát hiện phân vùng mất mát hoặc trôi dạt phân phối (data drift).
💡 Giải pháp DataPulse AI AGENTIC
  • Zero-PII Profiling: Trích xuất thống kê nén tổng hợp, không gửi raw data sang LLM.
  • Guarded Rule Proposer: Ép kiểu Pydantic Structured Output, neo nguồn gốc tham số.
  • Dual dbt Layer: Tách biệt lớp tiền xử lý chuẩn hóa và lớp thực thi kiểm thử.
⚙️ Core Tech Stack SYSTEM SPECS
  • Agent Framework: LangGraph (StateGraph 3 tầng).
  • Backend & API: FastAPI, Uvicorn, SQLAlchemy.
  • Data Engine: dbt-core, PostgreSQL 15, MinIO (S3).
  • Observability: Phoenix OpenTelemetry, LangSmith.
System Architecture

Kiến Trúc 3 LangGraph — Ranh Giới Lỗi Độc Lập

Tách biệt ranh giới trách nhiệm (Separation of Concerns) giúp hệ thống không bao giờ bị gián đoạn thực thi dữ liệu dù LLM gặp sự cố timeout hay quota.

🔵 Run 1: Proposal Graph 9 NODES
  • Profiler & Digest Tool: Quét thống kê nén, tính quantiles & distinct.
  • Semantic Understanding: Xác định vai trò cột (metric, ID, timestamp).
  • Candidate Builder: Sinh checklist ứng viên rule tất định.
  • Guarded Proposer: Gọi LLM sinh tối đa 5 rules Pydantic/bảng.
  • HITL Gate: Lưu `rule_proposals` chờ Steward duyệt.
🟢 Run 2: Execution Graph DETERMINISTIC
  • Test Generator: Biên dịch rule đã duyệt thành SQL và dbt YAML.
  • Artifact Validation: Kiểm tra cú pháp, lưu dbt config lên MinIO.
  • Read-Only Runner: Chạy SQL qua role DB bị giới hạn timeout.
  • Capped Sample Extractor: Lấy tối đa 20 ID vi phạm làm bằng chứng.
  • Persist Summary: Lưu kết quả vào `dq_runs` và `dq_results`.
🟣 Run 3: Anomaly Graph HYBRID INTELLIGENCE
  • Statistical Detectors: Robust Z-Score (Median/MAD), EWMA, Volume Drift.
  • Decision Aggregator: Tổng hợp score trọng số (NORMAL / WATCH / ANOMALY).
  • Hypothesis Agent (LLM): Chẩn đoán nguyên nhân gốc rễ (Root-Cause).
  • Steward Report: Xuất báo cáo Markdown + Khuyến nghị khắc phục.

🔵 Lớp 1: Pre-Profiling Transformation BASELINE CONTRACT

Vị trí: Ngay sau khi Ingest thô $\rightarrow$ Trước khi Profiler Agent quét.

  • models/analytics/profile_input.sql: View hợp đồng chuẩn hóa cung cấp dữ liệu sạch cho Agent.
  • schema.yml: Chạy data contract tests cơ bản (not_null, unique).

    CAST(vendor_id AS TEXT),

    CAST(fare_amount AS NUMERIC)

Governance & Data Security

Zero-PII Exposure: Nén Hồ Sơ Dữ Liệu Tổng Hợp

Đảm bảo an toàn bảo mật cấp doanh nghiệp: LLM không bao giờ được cấp quyền truy cập dòng dữ liệu thô (raw rows) hay thông tin nhạy cảm.

🛡️ Lợi Ích Cốt Lõi SECURITY
  • Không rò rỉ PII: Tên, địa chỉ, số điện thoại, thẻ tín dụng bị triệt tiêu hoàn toàn.
  • Tiết kiệm Token Context: Nén bảng 50,000 dòng thành 1 file JSON < 2KB.
  • Khả năng scale cao: Xử lý bảng hàng chục triệu dòng với chi phí LLM không đổi.

AI Safety & Guardrails

Chống Ảo Giác Tham Số (Parameter Provenance)

Giải quyết rủi ro lớn nhất của LLM trong Data Quality: Tuyệt đối không cho phép AI tự suy diễn hay "bịa" ra các ngưỡng kiểm tra không có chứng cứ.

❌ Cơ Chế Cũ (Rủi Ro Ảo Giác) VULNERABLE
  • LLM sinh đoạn văn tự do rồi hệ thống parse regex để tìm số.
  • Tự động default giá trị: ROW_COUNT = 50000, RANGE min = 0 khi thiếu thông tin.
  • Tự suy đoán tên cột cross-field không tồn tại trong schema.
✅ Cơ Chế Mới (Parameter Provenance) PROVEN ANCHOR
  • Bắt buộc neo nguồn gốc: Mỗi tham số (ví dụ: max: 6) phải liên kết trực tiếp với source_ref: "profile.profile_input.passenger_count.p95".
  • Extra Forbid: Pydantic từ chối mọi trường lạ hoặc payload không tuân thủ.
  • Missing Parameter: Bị validator từ chối (REJECTED_BY_VALIDATOR), không tự default.
🔍 Cấu Trúc Khai Báo Parameter Provenance Chuẩn JSON CONTRACT 
{
  "parameter_name": "max",
  "source_type": "DATA_PROFILE",
  "source_ref": "profile.profile_input.passenger_count.quantiles.p95",
  "derivation_method": "Upper bound capped at observed 95th percentile with domain headroom."
}
Human Governance

Human-in-the-Loop (HITL) & Immutable Ruleset Versioning

Đảm bảo quyền quyết định tối thượng thuộc về Data Steward trước khi đưa bất kỳ quy tắc nào vào môi trường kiểm thử production.

1. Review UI STEWARD ACTIONS
  • APPROVE: Chấp thuận rule do AI đề xuất.
  • EDIT: Sửa lại tham số (ví dụ: đổi max từ 6 thành 7) $\rightarrow$ Ghi nhận bản sửa.
  • REJECT: Từ chối rule không phù hợp kèm lý do.
2. Batch Locking CONSISTENCY
  • Không kích hoạt test run đơn lẻ sau từng click duyệt của Steward.
  • Khóa toàn bộ đợt review thành một **Review Batch** nhất quán trước khi chuyển sang bước tiếp theo.
3. Ruleset Versioning IMMUTABLE
  • Tạo RulesetVersionModel bất biến có mã băm SHA-256 (ruleset_hash).
  • Lưu vết kiểm toán (Audit Trail) ai duyệt, duyệt lúc nào trong bảng audit_events.
Execution Safety

Graph 2 Deep Dive: Deterministic SQL & Read-Only Runner

Mã thực thi kiểm thử được biên dịch hoàn toàn tất định bằng Template Engine, loại bỏ hoàn toàn việc để LLM tự viết SQL thực thi trực tiếp trên database.

🛡️ 4 Lớp Bảo Vệ Thực Thi (Execution Guardrails) SECURITY GATES
  • SELECT-Only Validator: Chặn triệt để các câu lệnh phá hoại (DROP, DELETE, UPDATE, INSERT).
  • Read-Only Database Role: Kết nối qua RUNNER_DATABASE_URL bị cô lập hoàn toàn quyền ghi.
  • Statement Timeout: Giới hạn thời gian truy vấn tối đa (tránh treo DB khi bảng hàng chục triệu dòng).
  • Capped Failure Samples: Giới hạn lấy tối đa 20 sample ID của các bản ghi vi phạm để phân tích.
⚡ Biên Dịch Parameterized SQL TEMPLATE ENGINE 
-- Biên dịch từ Rule RANGE [0.0, 500.0]
SELECT
    source_row_id AS failure_id
FROM analytics.profile_input
WHERE
    fare_amount IS NOT NULL
    AND (fare_amount < :min_val OR fare_amount > :max_val)
LIMIT 20;

-- Bind Parameters:
-- :min_val = 0.0, :max_val = 500.0
Statistical Intelligence

Graph 3 Deep Dive: Statistical Anomaly Engine (Median / MAD)

Phát hiện dị thường chuỗi thời gian dựa trên Thống kê Robust, không phụ thuộc vào LLM để đưa ra quyết định cảnh báo.

📐 Công Thức Robust Z-Score (Median / MAD) FORMULA
Robust Z = 0.6745 × (Current - Median) / MAD
  • Kháng Outlier: Sử dụng Median và Median Absolute Deviation (MAD) thay vì Mean/Std truyền thống.
  • Xử lý $MAD = 0$: Khi toàn bộ lịch sử đều có 0% vi phạm, tự động chuyển sang thang đo dự phòng (Fallback Scale).
  • Cửa sổ trượt 30 runs: Loại trừ các run thất bại và run đã được gán nhãn TRUE_ANOMALY.

LLM Root-Cause Reasoning

Root-Cause Hypothesis Agent & Actionable Insights

Tận dụng thế mạnh thực sự của LLM: Không dùng AI để đoán số, mà dùng AI để **suy luận ngữ cảnh và chẩn đoán nguyên nhân gốc rễ**.

🧩 Taxonomy Phân Loại Giả Thuyết (Hypotheses) CLASSIFICATION
  • PARTIAL_INGESTION: Thiếu file hoặc đường truyền gián đoạn.
  • LATE_OR_MISSING_PARTITION: Dữ liệu bị delay theo khung giờ.
  • SCHEMA_BREAKING_CHANGE: Cột bị đổi kiểu hoặc xóa.
  • UPSTREAM_TRANSFORMATION_CHANGE: Đổi logic POS/ETL.
  • DOMAIN_DISTRIBUTION_SHIFT: Thay đổi thói quen người dùng thực tế.
📋 Báo Cáo Chẩn Đoán & Khuyến Nghị Thực Tế OUTPUT 
{
  "hypothesis_type": "UPSTREAM_TRANSFORMATION_CHANGE",
  "summary": "Khả năng cao hệ thống POS vừa cập nhật phần mềm ghi nhận cước phí gây ra giá trị âm.",
  "confidence": 0.85,
  "recommended_checks": [
